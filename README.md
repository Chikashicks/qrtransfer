# QR File Transfer

PCの画面に連続表示したQRコードをスマホのカメラで読み取り、端末内でファイルに復元してダウンロードするWebページです。圧縮・解凍、符号化・復号はすべてブラウザ内で行い、ファイルの中身は外部に送信しません。

## 使い方

1. このリポジトリを GitHub Pages で公開する（Settings → Pages → Branch: `main` / root）
2. PCで公開URLを開き「送信」タブでファイルを選んで「表示開始」
3. Android の Chrome で同じURLを開き「受信」タブで「カメラ開始」し、PCの画面に向ける
4. 進捗が100%になりSHA-256一致と表示されたら「保存」

- 受信側：カメラはhttpsかlocalhostでのみ起動するため、`file://` で開くと動きません
- 送信側：QR生成を内蔵したため外部ライブラリが不要です。ダウンロードした `index.html` をChrome/Edgeで直接開けば、ネット接続なしで送信できます

## 設定と速度の目安

1秒あたりの送信量の上限は「FPS × QR数 × ブロック」です。実際の速度は、受信側で読み取れたQRの割合で決まります。

| 項目 | 既定 | 調整の方向 |
|---|---|---|
| QR数/画面 | 2 | 4にすると1画面の情報量は倍になるが、QR1個が小さくなり読み取りにくくなる |
| ブロック | 1000 byte | 読み取りが不安定なら 700 / 400 |
| FPS | 12 | カメラは通常30fpsのため15前後が目安。受信側の速度表示を見て調整 |
| 誤り訂正 | L | 映り込みが多い環境では M |

例：QR2個・12fps・1000byte なら上限約23KB/秒、QR4個・12fps・700byte なら約33KB/秒です。

- 送信前にブラウザ標準の CompressionStream(gzip) で圧縮します。テキストやCSVは数分の1になります。zip・画像・PDF・Office文書など圧縮済みの形式は、効果がないと判断してそのまま送ります
- 送信画面の下部に実測fpsを表示します。設定値に届かない場合は、PCの処理が間に合っていません

## 仕組み

- **QRの中身**：バイナリをBase45で英数字に変換し、QRの英数字モードで格納
- **QR生成**：英数字モード・誤り訂正L/M専用のエンコーダを内蔵（1個あたり数ms）。規格どおり8種類のマスクを評価して選ぶ。出力が既存ライブラリ（qrcode@1.4.4）と全バージョン・全マスクで一致することを確認済み
- **パケット**：先頭16byteのヘッダ（ファイルID・サイズ・ブロック長・seed、圧縮有無・QR数のフラグ）＋データ＋CRC32。50フレームに1回、ファイル名・MIME・元サイズ・元ファイルのSHA-256を含むメタ情報をQR1枠に入れる
- **表示**：次のフレームを裏のcanvasに描いておき、requestAnimationFrame（画面の描画周期）に合わせて切り替える
- **取りこぼし対策**：送信は「元ブロックK個 → 複数ブロックをXORした冗長パケット K/2個」の周期を繰り返す。受信側は単純な代入と、足りない分をGF(2)上のガウス消去で解く（Web Worker）。取りこぼし率によらず約K×1.01個の受信で復元できる
- **読み取り**：Chrome(Android)の `BarcodeDetector` で1枚の映像から複数のQRをまとめて読む。非対応環境では jsQR を使い、送信側の並べ方に合わせて画面を分割して読む
- **途中再開**：受信済みパケットはIndexedDBに保存。同じファイル・同じブロックサイズで再表示すれば続きから受信し、「保存中の受信データ」から再構築も可能

## テスト

```
npm i jsqr@1.4.0
node tests/core.test.js
```

Base45変換、パケットのCRC・フラグ、QR生成→読み取り、gzip圧縮・解凍、取りこぼし0〜50%・途中参加での復元を検証します。
