# QR File Transfer

PCの画面に連続表示したQRコードをスマホのカメラで読み取り、端末内でファイルに復元してダウンロードするWebページです。ファイルの中身は外部に送信しません（ページとQRライブラリの読み込みにのみネット接続を使います）。

## 使い方

1. このリポジトリを GitHub Pages で公開する（Settings → Pages → Branch: `main` / root）
2. PCで公開URLを開き「送信」タブでファイルを選んで「表示開始」
3. Android の Chrome で同じURLを開き「受信」タブで「カメラ開始」し、PCの画面に向ける
4. 進捗が100%になりSHA-256一致と表示されたら「保存」

カメラはhttpsかlocalhostでのみ起動するため、`file://` で直接開いても受信は動きません。

## 設定の目安

| 項目 | 既定 | 調整の方向 |
|---|---|---|
| ブロック | 1000 byte | 読み取りが不安定なら 700 / 400 に下げる |
| FPS | 10 | 取りこぼしが多ければ下げる。受信側の速度表示を見て調整 |
| 誤り訂正 | L | 画面の映り込みが多い環境では M |

転送速度は環境次第ですが、1フレーム約1KB・10fpsで毎秒約10KB程度が目安です（1MBで約2分、10MBで約20分）。

## 仕組み

- **QRの中身**：バイナリをBase45で英数字に変換し、QRの英数字モードで格納（バイナリモードより読み取り側の文字化けが起きない）
- **パケット**：先頭16byteのヘッダ（ファイルID・サイズ・ブロック長・seed）＋データ＋CRC32。10フレームに1回、ファイル名・MIME・SHA-256を含むメタ情報フレームを挟む
- **取りこぼし対策**：送信は「元ブロックK個 → 複数ブロックをXORした冗長パケット K/2個」の周期を繰り返す。受信側は単純な代入と、足りない分をGF(2)上のガウス消去で解く（Web Workerで実行し、計算中もスキャンを継続）。取りこぼし率によらず、受信できたパケットが約K×1.01個に達した時点で復元できる
- **途中再開**：受信済みパケットはIndexedDBに保存。同じファイル・同じブロックサイズで再表示すれば続きから受信し、「保存中の受信データ」から再構築も可能
- **デコーダ**：Chrome(Android)の `BarcodeDetector` を優先し、非対応環境では jsQR を使用。jsQR はQRバージョン23を読めない不具合があるため、送信側はバージョン23を24に上げて表示する

## テスト

```
npm i qrcode-generator@1.4.4 jsqr@1.4.0
node tests/core.test.js
```

Base45変換、パケットのCRC検査、QR生成→読み取り、取りこぼし0〜50%・途中参加での復元を検証します。
